# Voice references and implementation decisions

These notes apply the supplied references to the ongoing Senko voice-message implementation. They do not claim that an editor manual supplies a trained voice model.

| Reference | Finding | Application to Senko |
| --- | --- | --- |
| [RealtimeVoiceChat](https://github.com/KoljaB/RealtimeVoiceChat) and its [audio module](https://github.com/KoljaB/RealtimeVoiceChat/blob/main/code/audio_module.py) | Separates recognition, reasoning and synthesis; handles cancellation and buffers audio based on measured production timing. | Keep synthesis isolated in a terminable worker, retain bounded queues, measure real rendering time and test cancellation. Full duplex microphone capture and WebSocket streaming have not been added to this message-attachment task. |
| [Voiceflow guide](https://www.voiceflow.com/blog/voice-chatbot) | End-to-end dialogue, context and real outcome testing matter alongside the TTS engine. | Preserve existing chat context, use concise topic-focused spoken scripts, and test real LLM-to-audio-to-browser delivery instead of treating a text response as success. |
| [Natural voice output article](https://dev.to/voice_developer/10-tips-for-getting-natural-sounding-ai-voice-output-66n) | Punctuation, delivery variation, listening feedback and device checks are useful design suggestions. | Normalize text and punctuation, escape untrusted markup, vary phrase delivery subtly, and retain browser/device-viewport checks. API examples are not treated as universal capability claims; controls were checked against the actual engine reference. |
| [Official VOCALOID reference manual](https://rsc-net.vocaloid.com/assets/pdf_files/bb/VOCALOID_Reference_Manual_ENG.pdf), PDF pages 50?56 | Identity/formants, breath, dynamics, articulation and pitch/timing are separately editable aspects of expression. | Keep Senko's formant definition fixed; blend warm/bright/airy performance layers and apply bounded phrase-level pitch, pace and dynamics. This adopts a design principle, not Yamaha algorithms, voice data or a claim of VOCALOID fidelity. |
| [Rust vocaloid crate source](https://docs.rs/vocaloid/latest/src/vocaloid/lib.rs.html) | Reads local syllable WAV assets, concatenates them, and adjusts playback/pitch through resampling. | It requires a recorded syllable bank and does not furnish Senko's missing recordings or trained weights. No dependency or assets from this crate were adopted. |
| [Vocaloid 3 manual on Scribd](https://www.scribd.com/document/239606477/Vocaloid-3-manual) | The publicly readable text describes selecting a singer and iterating expressive parameter curves. | Use the current official manual as the primary technical reference. No paid download or voicebank extraction was attempted. |

Engine-specific support was verified against the [eSpeak NG markup reference](https://github.com/espeak-ng/espeak-ng/blob/master/docs/markup.md). The renderer uses supported sentence/prosody/break tags. Callers send plain text: user input never becomes executable SSML. Paragraph punctuation and dashes are normalized, short pauses are inserted between sentences, questions receive a small pitch/pace change, and quiet moods use restrained dynamics. The same bank supplies every phrase; there is no sentence-by-sentence speaker switching.

## What the tests establish

The initial Whisper tiny.en run failed, including a repeated-word hallucination. The same audio was compared with an unmodified engine reference using Whisper base.en; the allegedly garbled sentence was recognized correctly. The stronger recognizer became the evaluation tool with unchanged pass thresholds. Failed results remain in `.data/voice/original/evaluation/iteration-1-results.json`; pre-phrase-control results are in `before-phrase-controls.json`.

A successful recognizer result establishes a limited intelligibility check. It does not prove that this authored formant bank sounds natural, sounds like Miku/Teto, or meets the user's preferred character identity. It also does not turn the bank into a neural model trained from scratch. Listening feedback remains the relevant next input for subjective timbre tuning.
